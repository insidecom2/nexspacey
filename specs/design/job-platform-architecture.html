01 / RECOMMENDATION

เริ่มด้วย Modular Monolith

ยังไม่ควรแยกเป็น Microservices ในระยะแรก เพราะระบบเริ่มต้นมีขอบเขตไม่ใหญ่ และการรวมโค้ดไว้ในแอปเดียวจะพัฒนาได้เร็วกว่า

พัฒนาเร็ว

ใช้ Next.js เป็นทั้ง UI, API และ Server-side logic ในโปรเจกต์เดียว

แยกขอบเขตชัด

แบ่งเป็นโมดูลตามธุรกิจ ทำให้ภายหลังย้ายบางส่วนออกเป็น Service ได้ง่าย

ต้นทุนต่ำกว่า

ลดภาระการดูแลระบบหลาย Service, Message Broker และ Deployment หลายชุด

03 / BUSINESS DOMAINS

แบ่งระบบตามบทบาทและธุรกิจ

โครงสร้างนี้ช่วยให้ทีมเข้าใจเจ้าของข้อมูลและสิทธิ์ของแต่ละส่วนได้ง่าย

Candidate / ผู้สมัครงาน

  • สร้างโปรไฟล์และเพิ่มทักษะ
  • อัปโหลด Resume
  • ค้นหาและบันทึกงาน
  • สมัครงานและติดตามสถานะ

Employer / นายจ้าง

  • สร้าง Company Profile
  • ลง แก้ไข และปิดประกาศงาน
  • ดูรายชื่อผู้สมัคร
  • เปลี่ยนสถานะและดาวน์โหลด Resume

Admin / ผู้ดูแลระบบ

  • ตรวจสอบประกาศงานและบริษัท
  • จัดการรายงาน Spam
  • Suspend User / Company
  • ตรวจสอบ Audit Log

Shared Services

  • Authentication และ RBAC
  • Notification
  • File Storage
  • Search และ Moderation

04 / DATA MODEL

ข้อมูลหลักและสถานะ

ออกแบบสถานะให้ชัดตั้งแต่ต้น เพื่อรองรับการค้นหา การติดตาม และการตรวจสอบย้อนหลัง

กลุ่มข้อมูลตารางหลักข้อควรมี
ผู้ใช้งานusers, candidate_profilesRole, โปรไฟล์, ทักษะ และ Resume
บริษัทcompanies, company_membersเจ้าของบริษัทและสิทธิ์สมาชิก
ประกาศงานjob_posts, job_skillsสถานะ, วันหมดอายุ, สถานที่, เงินเดือน
การสมัครapplications, application_status_historyกันสมัครซ้ำและเก็บประวัติการเปลี่ยนสถานะ
ความปลอดภัยreports, audit_logsSpam, การตรวจสอบ และการเปลี่ยนแปลงสำคัญ

Job Post Status

draft→pending_review→published→paused / closed / expired

Application Status

submitted→reviewing→shortlisted→interview→offered / rejected
Constraint สำคัญ: กำหนด Unique Constraint ที่ (job_id, candidate_id) เพื่อป้องกันผู้สมัครสมัครงานเดิมซ้ำ
05 / UI DIRECTION

Clean, Trustworthy, Content-first

แพลตฟอร์มหางานควรทำให้ผู้ใช้เห็น “งานที่เหมาะสมและปุ่มสมัคร” ได้เร็ว โดยไม่ใช้เอฟเฟกต์ที่รบกวนการอ่าน

Color

Navy / Slate สำหรับข้อความและความน่าเชื่อถือ ใช้ Blue หรือ Teal เป็นสี Action และใช้สีสถานะร่วมกับข้อความหรือไอคอน

Typography

Noto Sans Thai หรือ IBM Plex Sans Thai, body อย่างน้อย 16px, line-height 1.5–1.75 และควบคุมความยาวบรรทัดให้อ่านง่าย

Components

Card ขอบบาง เงาเบา Radius 12–16px, ใช้ไอคอน SVG ชุดเดียว และมี Focus / Hover / Loading state ครบ

Responsive

ออกแบบ Mobile-first, Filter เป็น Bottom Sheet บนมือถือ, ปุ่มสมัครเป็น Fixed CTA และไม่ให้เนื้อหาถูกบัง

Accessibility

Contrast อย่างน้อย 4.5:1, ปุ่มกดอย่างน้อย 44px, มี Label ทุกฟอร์ม, รองรับ Keyboard และ Reduced Motion

07 / MVP ROADMAP

ขอบเขตที่ควรทำก่อน

โฟกัสที่เส้นทางหลักของ Candidate และ Employer ให้ครบก่อนเพิ่มฟีเจอร์ที่ซับซ้อน

Phase 1

  • สมัครสมาชิกและ Login
  • Candidate / Employer Profile
  • สร้างบริษัทและลงประกาศงาน
  • ค้นหา กรอง และบันทึกงาน
  • สมัครงานพร้อม Resume
  • Employer จัดการผู้สมัคร
  • Admin ตรวจสอบประกาศ

Phase 2

  • Email และ In-app Notification
  • ระบบ Chat
  • Employer Verification
  • Resume Builder
  • Spam Protection
  • Featured Job

เพิ่มภายหลัง

  • ระบบแนะนำงาน
  • Paid Post
  • Analytics สำหรับนายจ้าง
  • Meilisearch / Elasticsearch
  • Mobile App
08 / IMPORTANT RISKS

เรื่องที่ควรวางแผนตั้งแต่ต้น

สิ่งเหล่านี้เกี่ยวกับความน่าเชื่อถือ ความเป็นส่วนตัว และคุณภาพของประกาศงาน

Trust & Moderation

  • ประกาศต้องมีวันหมดอายุ
  • รองรับ pending review
  • รายงาน Spam และนายจ้างหลอกลวง
  • เก็บ Audit Log

Security & Privacy

  • ตรวจสอบสิทธิ์ทุก Route และ Action
  • Resume ไม่ควรเป็น Public URL
  • ตรวจสอบไฟล์ที่อัปโหลด
  • Rate limit การสมัครและลงประกาศ
คำแนะนำด้านการค้นหา: เริ่มจาก PostgreSQL Full-Text Search ก่อน เมื่อข้อมูลเริ่มมากค่อยเพิ่ม Meilisearch หรือ Elasticsearch ไม่จำเป็นต้องเพิ่ม Search Engine ตั้งแต่วันแรก
หลักสำคัญด้านโค้ด: อย่าให้หน้า UI ติดต่อ Database โดยตรง ให้เรียกผ่าน Service / Use Case และตรวจสอบ Authentication, Authorization และ Validation ทุกครั้ง
